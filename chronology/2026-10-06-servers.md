# 2026-10-06 · Servers: Rover Run retold for running an online service

User brief: reformulate the game for "should we buy or increase server capacity?" with no terrain
map (a 2D chart of time instead); fixed cards; marketing as the dodge move; funds as the battery,
full or zero; users as a person, a person with a dog, and a dog walker; the aesthetic and the game
almost exactly Rover Run's. Built in top-level `servers/` so Rover Run is untouched.

## Decisions

- **One-to-one mapping** (see `servers/README.md`): queries = slope (whisper / chatter / flood),
  users = ground (many / few / GONE), servers = dust (cool / warm / BURNING), funds = battery
  (full / empty, the money you arrive with). Moves: Scale up / Market / Apply for funds.
- **The dodge is "Market".** Marketing naturally saves a user collapse but not a meltdown; the
  story is that you spend the month on outreach instead of growth. "Pause" was offered, and the
  user's word was kept.
- **A new deck, not Rover's relabelled.** The story: quiet launch, growth, viral flood (4–5),
  lull, second surge (8–9), summer slump (10–11), festival flood (13). Same laws: GONE only after
  few and never into a flood (false alarms at 4, 8, 12); BURNING only after warm and only with real
  traffic (warm → whisper never burns; warm → traffic burns 3 of 4); funds empty after each hazard.
  The first draft had only one clean few-before-flood case; adding the second surge month (9) fixed
  "ignoring queries costs 2+".
- **The map is a chart:** the demand curve (from the deck's query levels, `tools/chart.mjs`) with
  parallel contour-like lines that bunch where demand climbs steeply. Same dot matrix, tint and
  strips.
- **Deaths:** GONE = washout (the sandstorm screen), BURNING = a new **burn** (the chart catches fire
  from the bottom, dots rise as embers), broke = TV off.
- **Tuning matches Rover Run exactly** (22 turns): look ahead users + servers 11; the model 10;
  ignore the query level 8; market any warning 6; always market 3; always scale 2; random 1.0.
  All 21 checks pass.

## Bugs caught while building

- The automatic rename turned Rover's internal state `'dead'` (death screen playing) into `'empty'`
  along with the battery value. It was harmless but confusing; restored.
- The first engine/analysis rename half-renamed the run's battery field; both were rewritten cleanly
  in the new vocabulary instead.

## Blind playtest (Cursor agent, GPT-5.6 Sol: 3 Medium runs, then 2 Hard)

Scores 3, 7, 7, 7, 7; it finished every run after the first. It learned the death conditions and
the funds rule exactly (apply before months 4, 5, 8, 9, 12, 14: 12/12). On Hard it chose
users + servers on purpose.

**It never used a leading indicator** (few → GONE, warm → BURNING), because Medium and Hard show
the month ahead's users and servers cards, i.e. the hazards themselves. Its rule was "market when
the month ahead is BURNING or GONE". Rover Run has the same gap (Medium shows ground and dust
ahead; Hard's best pair is ground + dust): the indicator lesson lives only in the Easy-mode exercise.
It also settled on a survivable superstition (marketing through most safe months, score 7 of a
possible 11), because nothing on screen explains scoring.

Other friction: the funds card (money on arrival) next to the live funds state; "market when
BURNING" felt arbitrary; no explanation of lives lost or of scoring; the chart is dense and
low-contrast.

Proposed fix, for both games: look-ahead shows only the **indicator** layer of the month ahead (or
none), never its hazard cards, so the room has to reason from the previous month's warnings plus
the context card. See the reply of 2026-10-06.
